# 065104 Packet — Main Inverter Data (T06NNNN)

## What it is

The `065104` packet (header bytes `major=0x06, n0=0x51, n1=0x04`) carries live inverter data: PV input power, per-string voltage/current/power, AC output power, temperatures, and energy totals. This is the Growatt T06NNNN family in grott's terminology — grott falls back to this layout for any `n1=0x04` packet.

The packet appears every ~2 minutes (paired with a 065120 grid-meter packet at the same timestamp). Each packet contains 192 four-byte chunks (768 bytes of data after the 60-byte serial header).

## The alignment problem

Our `bulk-print` reads the body as 32-bit big-endian chunks starting at `body[60]`. The T06NNNN format uses 16-bit Modbus registers, but those registers **start at body byte 67** — 7 bytes past where our chunk reading begins.

Body layout:
```
body[60..65]  6 bytes  date (year, month, day, hour, min, sec)
body[66]      1 byte   unknown separator
body[67..]    16-bit Modbus registers, 2 bytes each
```

Because 7 % 4 = 3, every register field starts at byte position **1 or 3** within our 32-bit chunks — never at position 0 where a clean 32-bit read would work. Fields therefore straddle chunk boundaries.

## Extracting values from bulk-print output

For a field at grott layout value `V` (the byte offset in grott's hex-string notation):

```
body_byte  = V / 2 - 8          (convert grott char-offset to body byte)
chunk_idx  = (body_byte - 60) / 4
byte_pos   = (body_byte - 60) % 4   # always 1 or 3 for T06NNNN fields
```

**2-byte field at byte_pos 1** (e.g. pv1voltage, pv1current):
```
value = (chunk[chunk_idx] >> 8) & 0xFFFF
```

**2-byte field at byte_pos 3** (e.g. pvstatus, recortype1):
```
value = (chunk[chunk_idx] & 0xFF) << 8 | (chunk[chunk_idx+1] >> 24) & 0xFF
```

**4-byte field at byte_pos 1** (e.g. pvpowerin/ppv, pv1watt, pv2watt):
```
value = (chunk[chunk_idx] & 0x00FFFFFF) << 8 | (chunk[chunk_idx+1] >> 24) & 0xFF
```

## Notes on unresolved fields

The 065104 packet contains 192 chunks (384 sixteen-bit registers) but the grott T06NNNN layout only defines ~30 fields. Most of the remaining data (chunks 30–191) is uncharted. Some chunks with stable, slowly-varying values that may be worth investigating:

- `065104.020`: decreases 228→219 over 30 min (unknown field, small integer)
- `065104.136`: increases monotonically (~512 per 2 min), likely an energy counter
- `065104.140`: slowly decreasing ~240-range hi-byte values
